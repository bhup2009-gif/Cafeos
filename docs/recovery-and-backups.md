# Recovery and backups

## Access keys

Initial credentials are generated by `scripts/provision-platform-admin.ts` into ignored `data/platform-credentials-*.txt` files with owner-only permissions. Admin login requires ID + password + any ONE of three keys. Store the keys separately. Replace an individual lost key in `/platform` after re-entering current credentials. Replacement revokes all admin sessions and displays the new key once.

## Total credential loss or broken admin UI

An authorized server operator can use `scripts/recover-platform-admin.ts`. Set `CAFEOS_RECOVERY_ADMIN_ID`, load the private database environment, and pass `--rotate-all`. It generates a replacement password/three keys into a new owner-only local file, revokes all admin sessions and records an audit event. There is no public recovery bypass or master password. Keep independent access to hosting, database and this runbook. Email-based recovery is not implemented yet.

Platform admins can reset an outlet owner's credentials through the dashboard. Existing owner sessions are revoked; saved orders/financial records remain intact.

## Backups

Run `node --env-file=.env.local --import tsx scripts/backup-cloud.ts` to create an AES-256-GCM encrypted snapshot under `data/`. An owner-only `data/cloud-backup.key` is generated once. Keep this key separately and copy both to secure off-site storage. The backup contains tenants, outlets (including inline uploaded images), admin credential hashes and audit history. It excludes global sessions and login attempts. Expired subscribers are included.

`restore-cloud.ts` requires `CAFEOS_BACKUP_FILE`, the encryption key, and `CAFEOS_RESTORE_CONFIRM=EMPTY_DATABASE_ONLY`. It restores only into a separately migrated empty target database and clears outlet sessions. It refuses to overwrite nonempty target tables. Test restores independently; code rollback does not restore data.

These are operator-run tools. No automated schedule, off-site storage or full restore drill is configured by this release. Before production, define recovery objectives/frequency, configure scheduled off-site backups and monitoring, and perform an isolated restore drill. Provider backups and account recovery must also be arranged separately.
